# PJR-HW09 移行後のアプリを人の目で通しで操作して確かめる

## 1. 概要

移行の後のアプリを、人が通しで操作して確かめていない。自動のテストで拾えない、操作の感触・表示の崩れ・文言の違いなどを、人の目で確かめる。

## 2. 完了条件

- 移行の後（`feature/frontend-test-upgrade` の先頭）の開発サーバー（`docker compose up` か `dashboard` の `npm run dev`）と、ローカルの API で確かめる。必要なら移行の前（`develop`）とも比べる。
- 確かめる流れ: トップ、規約への同意、かんたん見積もり・くわしく見積もり・災害のモードを結果まで、戻る操作、共有リンクの作成と読み込み（QR コードを含む）、結果の画像の保存、エラー画面と戻り先、ページが見つからない画面。
- PC のブラウザーと、スマートフォン（実機かブラウザーの開発者ツール）の両方で確かめる。
- 確かめた手順・環境・結果（問題があれば画面と手順）を「4. 対応結果」に記録する。見つかった問題は別の項目に分ける。
- 手順書は orchestrator が用意する。
- 上流の文書・コード・コメントに、登録簿の ID やリンクを書かない。登録簿との対応は commit メッセージの `Refs:` 行だけで取る。
- 保護された設定（`package.json`、`.github/workflows/**` など）の変更が必要な場合は、変更案を「4. 対応結果」に書き、反映は利用者の承認のもとで行う。依存の追加は、流す前に orchestrator が入れる（exec の executor はネットワークに出られない）。

### 3.1. 手順書（2026-11-01、specdojo-orchestrator）

**準備**

1. `../OpenFisca-Japan` で、移行の後の版（`feature/frontend-test-upgrade`、2026-11-01 時点は `378eb36`）を checkout する。項目を流していないときに行い、終わったら元のブランチに戻す。
2. `docker compose up --build -d` で起動する（API は 50000、画面は 30000）。または `dashboard` で `npm ci` と `npm run dev`。
3. PC のブラウザーで `http://localhost:30000` を開く。スマートフォンは、実機（同じネットワークから）か、ブラウザーの開発者ツールの端末の表示で確かめる。
4. 比べたい場合は、移行の前の版（`develop`）でも同じ手順を流す。

**確かめる流れ**（各項目で、表示の崩れ・文言・操作の反応・フォーカスの動き・読み込みの遅さを見る）

| No  | 流れ                 | 確かめること                                                                                                                                           |
| --- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | トップ               | 見出し・画像・3 つの見積もりのボタン・フッターのリンクが表示される                                                                                     |
| 2   | 規約への同意         | ボタンを押すとダイアログが開き、2 つの「了解しました」を押すと「利用開始する」が押せる。閉じるボタンで閉じる                                           |
| 3   | かんたん見積もり     | 住所・年収・配偶者・子どもの人数に答えて結果まで進む。途中で「戻る」を押し、前の答えが残っている                                                       |
| 4   | くわしく見積もり     | 子どもがいる家族で最後まで答え、結果まで進む。年齢や人数の入力で、全角の数字や上限を超える値を入れてみる                                               |
| 5   | 災害のモード         | 「地震被災者支援制度見積もり」から最後まで答え、結果まで進む                                                                                           |
| 6   | 結果                 | 給付・貸付の見出しと制度の行を開閉し、金額・説明・リンク・地図のリンクを確かめる                                                                       |
| 7   | 共有                 | 「結果のリンクをコピー」で得たリンクを別のタブで開き、同じ結果が出る。QR コードが出る場合は読み取れる                                                  |
| 8   | 画像で保存           | 「このページを画像で保存」で画像が保存され、内容が崩れていない                                                                                         |
| 9   | エラー               | API を止めた状態（`docker compose stop openfisca`）で結果まで進み、エラー画面と「戻る」の戻り先を確かめる。終わったら `docker compose start openfisca` |
| 10  | ページが見つからない | `http://localhost:30000/no-such-page` を開く                                                                                                           |
| 11  | キーボード           | Tab と Enter・Space だけで、トップから結果まで進めるかを試す                                                                                           |

**記録**

- 確かめた日・ブラウザーと端末・版（commit）・結果（問題なし／問題あり）を、上の表の No ごとに「4. 対応結果」に書く。問題があれば、画面の画像と手順を残し、別の項目に分ける。
